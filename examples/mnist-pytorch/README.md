# MNIST PyTorch Example

A mature model training example for Coach: a Convolutional Neural Network on the MNIST dataset using PyTorch.

## Structure

```
mnist-pytorch/
├── pyproject.toml        # Project metadata + dependencies
├── uv.lock               # uv dependency lock file
├── get-data.py           # Download MNIST into data/ (run once locally)
├── train.py              # Read from /data, train, write to /output
├── scripts/
│   └── inference         # Container-side inference script (executable)
├── Dockerfile            # Python 3.14 + uv + locked deps + scripts/
├── run.sh                # Build image & run with Coach
├── .gitignore            # Excludes generated files
├── data/                 # MNIST data (generated by get-data.py, git-ignored)
└── output/               # Artifacts (ignored)
```

## How it works

1. **Provision data** — run `get-data.py` locally to download MNIST into `data/mnist/`. Coach fingerprints this folder.
2. **Dependencies locked** — `pyproject.toml` declares `torch` and `torchvision`. `uv.lock` pins exact transitive versions.
3. **Build image** — Dockerfile installs `uv`, then runs `uv pip sync --system pyproject.toml` to reproduce the locked environment.
4. **Coach run** — mounts `data/` into `/data`, runs the container, writes artifacts to `/output`.

`train.py` never downloads anything. If `/data/mnist/` is missing, it exits with an error telling you to run `get-data.py` first.

## Prerequisites

- [uv](https://docs.astral.sh/uv/)
- Docker
- Coach CLI

## Quick start

```bash
# 1. Download MNIST (one time)
python3 examples/mnist-pytorch/get-data.py

# 2. Build and run with Coach
./examples/mnist-pytorch/run.sh
```

Or manually:

```bash
cd examples/mnist-pytorch

# Install deps (optional — for local IDE support)
uv sync

# Build image
docker build -t coach-example-mnist-pytorch:latest .

# Run with Coach
cd ../..
go run ./cmd/coach run \
    -model coach-example-mnist-pytorch:latest \
    -data ./examples/mnist-pytorch/data \
    -output ./examples/mnist-pytorch/output
```

## Artifacts

Each run produces an artifact folder keyed by the fingerprint of `(model_digest + data_checksums)`:

- `model.pt` — saved checkpoint with metadata
- `metrics.json` — per-epoch loss, accuracy, and timing

The `model.pt` is not just raw weights — it contains a full checkpoint dict:

```python
{
    "state_dict": {...},          # model weights
    "config": {"epochs": 3, ...}, # training config
    "architecture": "ConvNet",    # model name
    "input_shape": [1, 28, 28],   # expected input
    "num_classes": 10             # output classes
}
```

This makes the artifact self-describing — any inference script can inspect the checkpoint to understand how the model was trained and what input it expects.

## Inference with `coach run-script`

The container includes an inference script at `/scripts/inference`. After training, run it directly through Coach:

```bash
coach run-script \
  coach-example-mnist-pytorch:latest \
  inference \
  --samples 20 \
  --dump-metrics
```

Coach automatically mounts `./data` → `/data` and `./output` → `/output` into the container. The script auto-discovers the latest artifact under `/output` (any subdirectory containing `model.pt`).

With custom directories:

```bash
coach run-script \
  -data ./examples/mnist-pytorch/data \
  -output ./examples/mnist-pytorch/output \
  coach-example-mnist-pytorch:latest \
  inference \
  --samples 50
```

The script:
1. Discovers the latest artifact (newest `model.pt` under `/output`)
2. Prints checkpoint metadata (architecture, config, input shape)
3. Shows random sample predictions with ✓/✗ marks
4. Computes full test-set accuracy

## Notes

- Uses the **CPU** PyTorch wheel for a lighter image (~300MB vs ~4GB for CUDA).
- If you have a local GPU and want to use it, switch `pyproject.toml` deps to the CUDA index and update the base image.
- `uv pip sync` installs from the lock file, ensuring bit-for-bit reproducible builds.
